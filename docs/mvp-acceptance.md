# Mefice MVP 합격 조건 점검

`Mefice-Spec.md` 13장의 합격 조건을 하나씩 근거와 함께 확인한다. 근거는 다시 실행할 수 있는 테스트·측정으로 남긴다.

- 기준일: 2026-11-22 · 런타임: Claude Code CLI 2.1.304 · OS: macOS (arm64)
- 단위 테스트: `cd src-tauri && cargo test`
- 실제 CLI 통합 테스트 (모델 사용량 발생): `cargo test live_ -- --ignored --test-threads=1`
- 효율 비교 측정 (모델 사용량 발생): `MEFICE_BENCH_MODEL=haiku MEFICE_BENCH_REPS=2 cargo test bench_ -- --ignored --nocapture --test-threads=1` → `docs/bench/`

## 효율 측정 결과

원자료: [docs/bench/20261122-1444-haiku.md](bench/20261122-1444-haiku.md) (`.json` 동봉). haiku, 시나리오 3개 × 방식 5개 × 2회 = 30회, **30회 모두 완료 검사 통과**.

| 방식 | 같은 도구 기준 대비 비용 (시나리오별 평균) | 시간 | 해석 |
|---|---|---|---|
| baseline (사용자 설정 그대로의 터미널) | 232% · 332% · 253% | 9~12초 | 전역 MCP·도구 정의를 매번 싣는 비용. Mefice 고유 장점이 아니라 설정 차이 |
| baseline_same (같은 도구 제한의 터미널) | 100% (기준) | 6~8초 | 비교 기준 |
| direct (Mefice 직접 실행) | 75% · 117% · 98% | 9~11초 | **Mefice 자체 추가 비용은 측정 오차 수준**. 시간은 worktree 준비·스냅샷 등으로 2~3초 더 걸림 |
| pm (PM이 판단) | 93% · 117% · 110% | 10~12초 | 세 시나리오 모두 **위임 없이 PM이 직접 처리** (합격 조건 3). PM 지침·스키마로 소폭 증가 |
| pm_delegate (위임 지시) | 218% · 419% · 241% | 20~29초 | 위임 시 PM 계획 + 취합 고정 비용으로 2~4배. PM 비중 39~52%. 독립 작업은 실제로 2개로 분할·병렬 실행했지만 작업이 작아 더 느림 |

### 결론과 정책 제안

- 작은 작업에서 **위임은 비용 2~4배, 시간 2~3배**다. 현재 PM 정책(직접 처리 우선, 위임은 충분히 큰 작업만)이 측정으로 뒷받침된다. 스펙 5장 "관리 편의 대비 낭비가 크면 PM 호출과 분할 정책을 줄인다"에 따라 이 정책을 유지한다.
- PM이 직접 처리하는 경우의 추가 비용은 같은 도구 기준 대비 약 +5~15%다.
- **허용 추가 사용량 기준(스펙 14장 4번)은 사용자 결정 사항**이다. 측정값 기준 제안: PM 직접 처리 +20% 이내, 위임은 작업 하나가 같은 도구 기준 수 분 이상 걸리는 규모일 때만. 큰 작업에서의 위임·병렬 효과는 이번 측정 범위 밖이므로 실제 프로젝트에서 다시 측정해야 한다.
- 터미널 사용 비용을 줄이고 싶다면 Mefice와 같은 `--strict-mcp-config --tools` 제한이 가장 큰 효과를 낸다 (측정상 비용 약 1/2.5~1/3).

## 알려진 한계

- 비교는 한 모델(haiku), 작은 저장소, 시나리오 3개, 2회 반복 결과다. 실제 프로젝트 규모·모델에서는 다시 측정해야 한다 (스펙 5장: 한 번의 결과로 효율을 단정하지 않는다).
- 비용은 런타임이 계산한 API 정가 환산값이다. 구독 사용량은 별도의 구독 한도 사용률로만 확인할 수 있다.
- 작업 범위(폴더)는 지침으로만 전달되며 권한으로 강제하지 않는다. worktree는 파일 변경 격리 수단이지 보안 샌드박스가 아니다.
- 실행 중 질문 도구(`waiting_for_input`)는 지원하지 않는다. 질문은 PM `ask` 또는 텍스트 응답 + "이어서 실행"으로 처리한다.
- 시간 제한 타이머는 실제 CLI 통합 테스트가 없다 (사용자 중단 경로를 재사용하며, 그 경로는 검증됨).
- 트레이 아이콘·종료 확인 창은 실제 앱에서 사람이 눌러 확인하지 않았다 (진행 중 작업이 없을 때의 종료는 확인).
